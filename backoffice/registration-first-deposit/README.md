## 当前推荐设置

新会员从0天档参与，另有7天和1、3、6、12个月档。充值门槛为100、500、1,000 INR；同一时长每跨一金额档增加0.5个百分点。默认现金钱包、1倍打码、单人上限100、活动预算100,000；新建起一年。新建组合只选首充，其余充值优惠由通用充值赠送按需新增及启用，组合单笔预留上限250。

新会员首充1,000得到15，注册满6个月首充1,000得到35。五项全部开启且达标时，后者合计78。金额及文案由共享配置生成。

## 接入边界

这是本地交付，未接真实支付、钱包或资格服务。会员情境来自player-view.js中的数据入口，供核对界面；scenario=new/returning/used/unknown/credited只改变本地测试状态，不代表真实会员。页面未建立真实充值订单，也不进行真实派奖。

正式接入需提供租户币别与时区、会员及首充记录、活动期间和分层资格、预算并发预留、每日领取历史、通道回调幂等、退款修正、多语内容及权威结算状态。本地提供两种子选项，兼容原六类数据；随机奖励、全量资格与真实任务进度尚未接入。遇到未覆盖旧规则，保留原配置与权益，补齐模板并核对后才能切换。充值返佣范围尚未收到确认，暂保持原入口。充值管理的新增通道与返佣按钮只说明原入口职责，不实现支付后台编辑。

本次沿用奖励存储键ngss3.registration-first-deposit.launch及ngss3.deposit-reward-bundle.launch；支付控制使用ngss3.deposit-payment-settings；先前草稿保留在原键，不自动覆盖。已部署租户的真实活动不得被新建推荐设置覆盖。

## 两种子选项与达标周期

User-confirmed：7日按最近7日滚动统计。以本笔成功时间回溯168小时，包含下限、排除本笔及未来记录，只统计成功且符合活动方式和通道的充值。窗口不重置活动总次数和单人赠送上限。缺少历史时返回待核验，不能当成零。

通用赠送支持单次、累计、两者同时满足、指定金额；累计窗口为当日、滚动7日、活动开始后、历史累积。累计由未满变为达标时触发一次核验，百分比以触发本笔金额计算；后来窗口回落后再跨门槛仍受独立次数上限约束。历史累积包含活动启用前成功充值。上述非7日细节为Prototype-only建议，正式接入需按租户时区和既有权益确认。

每项活动可设置独立起止时间或始终开启。后者不受旧结束日期限制，首次启用记录累计起点；再次启用不清空已领取历史。规则周期和活动有效期是不同字段。

现网只读复核：充值弹窗宽800px、标签240px、输入360px、单列，32px控件、18px行距。活动弹窗保留推广默认表单与双栏；线上可见绿色背景及奖品图标24张通过浏览器素材工具复制到activity-assets，不含会员资料、账户头像或会话。推广为切换入口样式，非充值活动的保存与经济规则不在本次范围；当前确定按钮在推广视图禁用。

充值设置只移出累计充值赠送上限与钱包，打码倍数、角标、订单有效时间、频率、清除打码和放款额度保留。其倍数应统一用于通用赠送还是作为活动默认值，仍待使用者第二项答复；现有活动倍数未覆盖，充值设置数值目前单独存储。此待决项不可当作已实现的打码继承。

## 活动表单细节

有效会员标准的账号首充、充值、打码、充值次数使用四列横向布局，窄屏保留同一行并可横向滚动。移除使用推荐奖励按钮；按注册时长分档使用可键盘操作的开关，仍保留既有各档配置。奖励单元格通过明确间距分隔类型、数值和单位。

首充试算仅显示本次金额与已注册天数，隐藏周期内已充值金额和通道选择；试算自动选用该活动适用的通道，避免隐藏旧选择导致错误的不适用结果。非首充试算继续保留周期金额与通道。

现金钱包显示打码输入；常规奖励使用倍数，指定金额／旧推荐金额继续保留绝对提款所需打码量，并移到上方基本资料。推广默认视图切到现金后也显示倍数。此次仅修正显隐，不决定尚待确认的全局倍数继承方式。

本轮30项既有DOM检查通过，另检查了分档开关来回切换、现金／彩金显隐、现金倍数保存、指定金额打码字段位置及首充银行范围试算。浏览器视觉验证限制沿用上文。
