01 / DESIGN PRINCIPLES

操作邏輯

本站預設與玩家選擇分開

  • 管理員決定本站預設及可開放的主題、配色。
  • 玩家只在允許範圍內選擇；預覽試選不改寫本站預設。

主樣式與細部設定分層

  • 預覽卡片：選元件佈局與視覺樣式。
  • 細部選項：按鈕組調呈現、開關控制顯示；多項清單用選擇器。

現行標記是評審依據

  • UI 與 PD／PM 比較現行與新設計，決定保留哪些選項、哪些直接替換。
  • 首頁由遊戲分類、排列與各區塊組合，不再用整頁版面總選項。

辨認狀態：側欄色塊表示正在編輯；高亮筆形圖示表示有修改。標題右側圖示顯示預設／覆蓋、恢復與開關，滑鼠停留或鍵盤聚焦可看說明。

02 / WORKFLOW

主要操作方式

  1. 找物件從左側分類或搜尋進入；分類可收折。
  2. 選樣式、調細節直接點選卡片，再調細部選項；不必先切換編輯模式。
  3. 看預覽與檢查切頁面、登入狀態與寬度；檢查列點一次即可看詳細。
  4. 核對並發布點「釋出」，比較當前與變更後，再點「確認釋出」。
03 / RECOVERY

恢復設定

只想改回一個設定，與整批放棄這次修改，是兩種不同操作。

04 / SCENARIOS

操作情境：我要做什麼？

評估現行樣式是否保留

操作UI 與 PD／PM 對照「樣式1（現行）」與新設計，比較使用情境及操作差異。

決定保留現行選項，或以新設計取代；並列展示不代表全部都會保留。

組合首頁

操作遊戲分類選主樣式，再調「細部設定」的分類按鈕與資金快捷區；遊戲排列、活動摘要分別調整。

結果用各區塊組合版面，沒有獨立的「首頁版面」總選項。

固定品牌、開放配色

操作在「主題與顏色」設定本站預設與玩家可選範圍，例如只開放橙白、藍白。

結果預設必須在允許範圍內；只留一種選項即可固定。

只試看，不改本站

操作在預覽選頁面、配色、主題；右上切換登入前後，底列調整寬度或輸入自訂值。

結果只改預覽情境；本站預設不變。只有一個可用主題時無法切換。

調整底部導航

操作登入前、登入後分別選入口，使用左右箭頭排序。

結果兩組獨立設定；位置不能空白，同組功能不能重複。

替換 App 下載位置

操作開啟該組「App 下載替代入口」，再選替代功能。

結果使用既有 App 槽位，不增加按鈕數；沒有 App 槽位時不適用。

補充入口或關閉區塊

操作「替代按鈕」選位置、功能、登入範圍；要隱藏元件則用標題旁開關。

結果不支援的位置或缺少必要入口會提示調整；必要元件不可關閉。

只恢復遊戲分類樣式

操作點該專案標題旁的恢復圖示，先看提示確認範圍。

結果樣式回到預設，其他修改保留；遊戲分類的細部選擇也保留。確認後再發布。

放棄這次全部修改

操作點「撤銷修改」，在確認視窗同意撤銷。

結果全部未發布修改回到上次發布版本，既有客製設定仍保留；不是全站恢復主題預設。

檢查並發布

操作點「配置檢查」的非零分類看詳細，處理 Block，確認需復核項；再點「釋出」。

結果核對「當前／變更後」，確認無誤後點「確認釋出」。預覽不等於發布。

05 / HANDOFF SPECIFICATIONS

前端與設計規格

前端開發人員

  • 現行樣式替換：依 UI／PD／PM 確認清單保留穩定 ID；被取代的選項需定義舊值對映及找不到對映時的回退，不可只刪卡片。
  • 恢復的界線：遊戲分類「恢復樣式」保留細部設定；全部撤銷則回到上次發布版本，不能改成全站 INHERIT。
  • 兩組導航：登入前後分開儲存；「我的／帳戶」視為同一入口。App 替代只佔用既有 App 槽位，不增加數量。
  • 相依驗證：替代入口要同時檢查承載位置、登入範圍及必要功能可達性；只在資料完全相同時跳過重複驗證。
  • 局部更新：切樣式保留輸入；App 開關不可重建原控制項。預覽頁面、登入狀態、配色及寬度不得寫入本站設定。

UI 設計師

  • 現行選項決策：與 PD／PM 逐物件確認現行樣式要保留或由新設計取代，列出新舊對應。
  • 依物件分類設計：未來新增樣式或主題，沿用這個後台的物件分類，例如遊戲分類、遊戲排列、底部導航；同一物件的不同設計放在同一類選項。
  • 分清樣式與細部設定：布局變化屬於主樣式；分類按鈕、資金快捷區等屬於細部設定，不另拆成新物件。
  • 新主題的物件對應：依既有分類提供各物件的樣式與預設搭配，標明哪些共用、哪些新增、哪些不適用。
  • 新增分類的條件：只有用途與既有物件不同時，才與 PD／PM 確認新增分類，避免同一功能因外觀不同而重複分類。
