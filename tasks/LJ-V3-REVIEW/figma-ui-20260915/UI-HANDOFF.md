## 好运探索季｜玩家 UI 设计交付

Lucky Journey · 2026-09-15 · 可编辑需求原型

### 设计目标

玩家看到一笔明确奖金，通过抽奖收集道具，推进同一条金额进度条。进度满后领取固定奖金。保留清晰层次，插画与视觉质感由 UI 设计师继续设计。

### 必须保留

金额是第一层级；百分比为辅助。
主流程：参加 → 获得次数 → 转盘 → 道具/谢谢参与 → 进度满 → 领取/派发。
次数字段表示当前可转次数，不显示后台解锁总次数、阶段或预算。

### 原型怎么阅读

02–05 区域：每张手机框是玩家界面，下方是设计与开发注解。
01：修改共用元件可同步画面。
06：先确认素材和状态契约，再开始视觉定稿。

### 证据标记

Prototype-only：当前本机原型行为。
Recommendation：补齐 UX 的建议，尚非已实现功能。
Open：需产品/后端确认。示例数字不是固定运营配置。

### 交付边界

本文件是活动需求原型，不代表生产接口已实现。不重做平台登录、充值、游戏或客服页面；按现有平台设计系统接入。没有真实会员或邀请标识。

## 规则与文案界线

把奖励、进度和钱包分清楚

### 金额与道具

金币 /100、宝石 /10,000、星钻 /1,000,000 转为总进度；三类道具都可能出现。它们不是现金奖，未满时金额不能计入“已发奖金”。

### 次数控制完成

每次合法抽奖消耗 1 次。谢谢参与消耗次数但进度不动；最后一次补满。只有在有效期内取得并使用足够次数，才完成固定次数路径。

### 玩家文案

使用“解锁进度”“抽奖次数”“获取抽奖次数”“领取奖金”。道具中奖可表达喜悦，同时显示实际数量和进度增量。
不要写“已提现”“再转一次必到账”或不存在的限时机会。

### 后台内容不放手机内

固定次数、快砍/中段/细砍、概率分配、完成度计算、预算、模拟完成、强制结果、派奖重试等放操作说明或开发工具。

### 当前源代码差异｜Open

当前后台是首转 min/max，旧需求是平均值 ±5%；normalize 与 engine 的兼容分支还存在差异。因此本稿只展示 90% 样本，不将 88–94 写成最终承诺。
手动领取与活动结束后的权益时限需确认。

## 版面与阅读规格

Design recommendation · 390 px 主稿

### 手机版层级

1 活动名称与状态
2 金额 / 目标现金 + 百分比 + 单一进度条
3 转盘、可用抽奖次数、主按钮
4 已发奖金与累计道具
5 获取抽奖次数：每日免费 → 好友助力 → 做任务

### 尺寸与滚动

主稿 390 × 844；窄屏 320 × 812；大屏 430 × 932。画面纵向滚动，主按钮不遮任务内容。16 px 页面边距、12–16 px 区块间距；弹窗左右至少 16 px。长弹窗可滚动。
原 HTML 的 390 px 含设备边框，Figma 手机框表示内容视口；不要把模拟器边框做进真实 H5。

### 文字与点击区域

金额 34/44；主标题 22/32；正文 16/26；标签 14/22；辅助文字 12/20。Noto Sans SC 为可用字体替代。实际品牌字体由 UI 定稿。
主按钮高 48 px；关闭与次要操作触达区至少 44 × 44 px（建议）。

### 适配要求

320 px：金额与目标允许分行，任务条件完整显示。
430 px：转盘保持 252 px 居中，不放大挤占内容。
桌面：复用站点外壳，中间约 430 px 活动列，不出现模拟器工具。

### 无障碍与动效

状态不只靠颜色；对话框有标题、焦点进入与返回、Esc 关闭，背景不可操作。正常约 950 ms 转盘动画；减少动效跳过旋转。所有结果依服务端数据，不依动画停止角度决定。

## 自订奖项素材规格

实际尺寸与建议交付分开列示

### 可配置内容｜Prototype-only

presentation.wheelImages：thanks / coin / gem / star 共 4 张；同种道具在重复扇区共用同一张图。
presentation.wheelNames：自订名称 1–6 字；空白回默认。当前代码按 JS 字符串 slice(0,6)，emoji 字符长度边界需开发处理。

### 目前显示尺寸

后台缩略图：64 × 64 px，contain，外容器圆形裁切。
转盘图槽：SVG 24 × 24 单位；254 viewBox 在 238 px 内盘显示，视觉约 22.5 px。
中奖弹窗：56 × 56 px，contain。
默认素材 SVG viewBox：64 × 64。

### 推荐交付｜不是上传限制

每项提供 192 × 192 px 透明 PNG（64 px 的 @3x）；有源矢量可另交 SVG。
重要轮廓放中央 144 × 144 px；四周保留透明留白。分别看 24、56、64 px 缩小效果。
奖品名称、数量、光效与图像分层，别把文字烘焙进图片。

### 命名与压缩

lj-prize-coin.png / lj-prize-gem.png / lj-prize-star.png / lj-prize-thanks.png
建议单张 ≤100 KB 作为交付目标，需开发确认正式限制。透明 PNG 或 WebP 优先；SVG 需平台安全处理。

### 当前上传边界｜Open

后台 accept=image/*，直接 FileReader 转 data URL。代码没有文件大小、像素、格式白名单及加载失败兜底校验；不能对 UI 宣称已有 2 MB 等限制。
生产需补格式/尺寸/体积校验、失败提示与默认图兜底。完成奖金图标不是第五个后台自订奖项。

## 数据与显示契约

字段含义是 UI 约束；API 名称待开发定义

### 金额进度

服务端权威：progressUnits 0–1,000,000，finishPrize 金额。
百分比 = progressUnits / 10,000，显示 4 位小数。
未完成金额向下取到分且小于目标；只有 1,000,000 units 才显示完整目标。
5.00 × 99.99% → 4.99，不能显示 5.00 已完成。

### 道具中奖

进度增量 = amount × scale：金币 10,000；宝石 100；星钻 1。
前端显示服务器给的道具数量与增量，不能用缩短后数字反推。累计道具最多 4 位小数、千分位；金额固定 2 位。

### 结果与状态

抽奖：requestId / spinId、道具类型与名称、数量、增量、当前进度、剩余次数。
权益：待领取 / 派发中 / 已入账 / 失败待重试；这些状态优先于“再次参加”。
配置：活动名称、奖金、有效期、来源开关与门槛、领取方式。

### 次数来源

免费：今日状态、本局已发/上限。
好友：每人次数、本局上限、是否充值和金额门槛、已确认次数。
任务：名称、累计值/门槛、可得次数、完成/待确认/已发/上限状态。累计值与待确认属建议接口。

### 不能从前端推导

正式资格、活动时区、好友归因、有效注单、充值确认、钱包到账均由后端返回。不要把点击去完成当完成，也不要在 UI 随机决定奖励或自行更改到期时间。

## 联动、异常与验收

给 UI 与开发一起走查

### 主要跳转

参加 → A02；转一次 → A07 → B01/B02/B03/B04；进度满 → 自动 B05，手动 B06，处理中 B07。
次数不足 → 同页滚动来源；邀请 → C04 → 复制成功/失败；去完成 → 复用平台充值/游戏页面 → 返回刷新。

### 优先处理的权益缺口｜Open

当前手动待领取会释放本局预留；允许重复参加时也可能覆盖待领局。应保留奖励与预留到入账/合法失效，旧奖励可追踪。
手动 + pending 分支与正常手动分支不一致；claimPrize 没有风控/请求失败分支。UI 须保留处理中及失败状态。

### 恢复与重复操作

动画期间锁主按钮。网络未知时查询同一请求，不能盲目新抽。重放同一 spinId 不重复弹窗或累计金额。
复制链接必须等待成功才提示；失败可重试或长按复制。

### 日期与到期｜Open

当前模拟器按天推进，前端尚未严格绑定开始/结束时间与真实时区；正式展示到期时间与小于一天文案需服务端剩余秒数。
已完成未领取的领取期限、活动截断后待发奖处理待确认。

### UI 交付验收清单

所有 A/B/C/D 状态有对应图；主操作和禁用理由清楚。
小屏无横向溢出，弹窗可完整读取；长名称/长金额不压按钮。
四种素材有小尺寸预览与透明底切图。
没有开发工具、后台概率/预算或不实到账承诺。
图稿连线、组件和状态标签保持可编辑。
